# Algorithm Specification: Topology-Aware 2D Hypercube Partitioning for GraphFrames Motif Joins

## 1. Problem Formulation

Let $G = (V, E)$ be a directed graph represented as a relational edge table $E(src, dst)$. A foundational 2-hop motif query $(a)-[e_1]\to (b)-[e_2]\to (c)$ evaluates the relational equi-join:
$$M = e_1 \bowtie_{e_1.dst = e_2.src} e_2$$

For any intermediate vertex $v \in V$, let $d^-(v) = |\{u \in V \mid (u, v) \in E\}|$ denote its in-degree, and $d^+(v) = |\{w \in V \mid (v, w) \in E\}|$ denote its out-degree. The total intermediate join cardinality (Cartesian workload) generated by vertex $v$ is given by:
$$W(v) = d^-(v) \cdot d^+(v)$$

In power-law graphs, a small subset of heavy hub vertices $H \subset V$ exhibits extreme workload density ($W(h) \gg 10^6$), while possessing a modest byte size that evades Spark Adaptive Query Execution (AQE) skew detection.

## 2. Formal Algorithm

```
Algorithm 1: Topology-Aware Degree-Balanced 2D Hypercube Partitioning
---------------------------------------------------------------------------------------------------------
Input:  Edge relation E(src, dst)
        Grid cell capacity budget P (default: P = 100)
        Computational work threshold θ_w (default: θ_w = 1,000,000)
        Uniform hash function hash: V -> Z

Output: Result relation M containing all 2-hop motif paths (a -> b -> c)
---------------------------------------------------------------------------------------------------------

/* Phase 1: Topological Profiling & Computational Hub Identification */
 1: D_out ← Group E by src, aggregating count as d+(v)
 2: D_in  ← Group E by dst, aggregating count as d-(v)
 3: D     ← Full outer join of D_out and D_in on vertex ID v, replacing nulls with 0
 4: For each vertex v ∈ D do:
 5:     W(v) ← d-(v) * d+(v)                            // Calculate Cartesian workload
 6: End For
 7: H ← Filter D where W(v) > θ_w                       // Identify heavy computational hubs

/* Phase 2: Degree-Balanced 2D Grid Allocation */
 8: H_meta ← ∅
 9: For each hub h ∈ H do:
10:     // Solve Lagrange multiplier for optimal aspect ratio:
11:     r_raw ← sqrt( (d-(h) * P) / max(d+(h), 1) )
12:     s_raw ← sqrt( (d+(h) * P) / max(d-(h), 1) )
13:     r     ← max(1, floor(r_raw))
14:     s     ← max(1, floor(s_raw))
15:     // Enforce grid capacity bound:
16:     If r * s > P then
17:         scale   ← sqrt( P / (r * s) )
18:         r_final ← max(1, floor(r * scale))
19:         s_final ← max(1, floor(s * scale))
20:     Else
21:         r_final ← r
22:         s_final ← s
23:     End If
24:     H_meta ← H_meta ∪ {(h.id, r_final, s_final)}
25: End For
26: Broadcast H_meta and H.id to all executor nodes

/* Phase 3: Hypercube Vertex-Cut Transformation (Hub Branch) */
27: // Partition and replicate incoming edges (e1: a -> h)
28: E1_hub ← E ⋈_{E.dst = H_meta.id} H_meta
29: E1_salted ← ∅
30: For each edge (u, h, r, s) ∈ E1_hub do:
31:     r_coord ← |hash(u)| mod r                       // Hash source into 1 of r rows
32:     For s_coord ← 0 to (s - 1) do                   // Replicate across all s columns
33:         E1_salted ← E1_salted ∪ {(u, h, r_coord, s_coord)}
34:     End For
35: End For

36: // Partition and replicate outgoing edges (e2: h -> w)
37: E2_hub ← E ⋈_{E.src = H_meta.id} H_meta
38: E2_salted ← ∅
39: For each edge (h, w, r, s) ∈ E2_hub do:
40:     s_coord ← |hash(w)| mod s                       // Hash destination into 1 of s columns
41:     For r_coord ← 0 to (r - 1) do                   // Replicate across all r rows
42:         E2_salted ← E2_salted ∪ {(h, w, r_coord, s_coord)}
43:     End For
44: End For

45: // Execute 3D compound join across virtual grid cells
46: M_hub ← Select (e1.src, e1.dst, e2.dst) from E1_salted as e1
            JOIN E2_salted as e2 ON
                e1.dst = e2.src AND
                e1.r_coord = e2.r_coord AND
                e1.s_coord = e2.s_coord

/* Phase 4: Relational Join for Unskewed Long-Tail (Non-Hub Branch) */
47: E1_nonhub ← E ⊳_{E.dst = H.id} H                     // Left anti-join: exclude hub dst
48: E2_nonhub ← E ⊳_{E.src = H.id} H                     // Left anti-join: exclude hub src
49: M_nonhub ← Select (e1.src, e1.dst, e2.dst) from E1_nonhub as e1
               JOIN E2_nonhub as e2 ON e1.dst = e2.src

/* Phase 5: Union and Final Result */
50: M ← M_hub ∪ M_nonhub
51: Return M
---------------------------------------------------------------------------------------------------------
```

## 3. Theoretical Proofs & Invariants

### 3.1 Correctness & Completeness Invariant
**Theorem 1 (Exact Coverage):** *Algorithm 1 produces every valid 2-hop motif path $(u \to v \to w)$ exactly once, introducing zero duplicate paths and zero false omissions.*

**Proof:**
Let $p = (u, v, w)$ be an arbitrary motif path such that $(u, v) \in E$ and $(v, w) \in E$.
1. **Case $v \notin H$:** The edges $(u, v)$ and $(v, w)$ are filtered exclusively into $E_{1,\text{nonhub}}$ and $E_{2,\text{nonhub}}$ through the left anti-joins (lines 47–48). The standard equi-join $e_1.dst = e_2.src$ evaluates them once on intermediate key $v$. They cannot enter $M_{\text{hub}}$ because $v \notin H_{\text{meta}}$.
2. **Case $v \in H$:** The hub $v$ has grid dimensions $(r, s)$ in $H_{\text{meta}}$.
   - Edge $(u, v)$ is deterministically mapped to row $r^* = |\text{hash}(u)| \pmod r$ and replicated over columns $s' \in \{0, \dots, s-1\}$.
   - Edge $(v, w)$ is deterministically mapped to column $s^* = |\text{hash}(w)| \pmod s$ and replicated over rows $r' \in \{0, \dots, r-1\}$.
   - The join predicate requires:
     $$(e_1.dst = e_2.src = v) \land (e_1.r\_coord = e_2.r\_coord) \land (e_1.s\_coord = e_2.s\_coord)$$
   - The coordinates match if and only if:
     $$r\_coord = r^* \quad \text{and} \quad s\_coord = s^*$$
   - Because $(r^*, s^*)$ is a single coordinate in the 2D grid $\{0, \dots, r-1\} \times \{0, \dots, s-1\}$, the join matches in **exactly one** virtual cell. Neither $(u, v)$ nor $(v, w)$ pass the anti-joins, ensuring $p \notin M_{\text{nonhub}}$.

Thus, $p$ is generated with multiplicity $1$. $\blacksquare$

### 3.2 Optimization Formulation & Lagrange Solution
For a heavy hub $h$, we seek grid dimensions $(r, s)$ that minimize the total shuffled communication cost $C(h)$ subject to the total cell budget $P$:
$$\min_{r, s} C(h) = d^-(h) \cdot s + d^+(h) \cdot r \quad \text{subject to} \quad r \cdot s \le P, \quad r \ge 1, \quad s \ge 1$$

Applying the Lagrange multiplier $\mathcal{L}(r, s, \lambda) = d^-(h)s + d^+(h)r - \lambda(P - rs)$:
$$\frac{\partial \mathcal{L}}{\partial r} = d^+(h) + \lambda s = 0 \implies \lambda = -\frac{d^+(h)}{s}$$
$$\frac{\partial \mathcal{L}}{\partial s} = d^-(h) + \lambda r = 0 \implies d^-(h) - \frac{d^+(h)}{s} r = 0 \implies \frac{r}{s} = \frac{d^-(h)}{d^+(h)}$$

Substituting $s = \frac{P}{r}$ into the optimal ratio yields:
$$r \approx \sqrt{\frac{d^-(h) \cdot P}{d^+(h)}}, \qquad s \approx \sqrt{\frac{d^+(h) \cdot P}{d^-(h)}}$$

### 3.3 Complexity & Communication Bounds

| Dimension | Standard Relational Join (Catalyst / AQE) | Naive 1D Salting ($P$) | Proposed 2D Hypercube ($r \times s \le P$) |
| :--- | :--- | :--- | :--- |
| **Max Work per Task** | $O(d^-(h) \cdot d^+(h))$ *(Unbounded)* | $O\left(\frac{d^-(h) d^+(h)}{P}\right)$ | $O\left(\frac{d^-(h) d^+(h)}{P}\right)$ |
| **Replication Overhead** | $0$ | $O(P \cdot d^+(h))$ | $O(\sqrt{P} \cdot (d^-(h) + d^+(h)))$ |
